# Lab 10 reference

`InvoiceApprovalSolution_Reference/` is the BPMN solution from the 2026-10-02 dry run, where both paths (the
auto-approved invoice and the reviewer-approved invoice) ended Paid with one RecordId carried end to end. It is
renamed from the participant's name to `Reference` and stripped of every tenant value. Copy its shapes, never its
names or placeholders.

```
InvoiceApprovalSolution_Reference/
  InvoiceApprovalSolution_Reference.uipx           solution manifest (keep it in git; it reopens the solution)
  InvoiceApprovalProcess_Reference/
    InvoiceApprovalProcess_Reference.bpmn          the process
    entry-points.json                              hand-written: FileName input on Event_start
    bindings_v2.json                               hand-written: v2.2 process bindings, name + folderPath
    operate.json, package-descriptor.json, project.uiproj
```

Not included: `resources/` (refresh recreates it, and in the dry run it held the signed ERP token),
`userProfile/` (debug overwrites with tenant and user ids), build zips, and the scaffold's `AGENTS.md` /
`CLAUDE.md`.

The release key is a literal per participant: replace each `releaseKey` with your own process key from the Lab 10
Step 1 readiness table. In `bindings_v2.json`, `Agentic Bootcamp/APAutomation_Reference` becomes
`Agentic Bootcamp/APAutomation_<user_name>`. The local ids in the manifest and `operate.json` (SolutionId,
project Id, projectId) and the entry point `uniqueId` are generated by `uip solution init` / `uip maestro bpmn init`;
your scaffold makes its own.

## The five runtime rules this file follows

1. Every `Orchestrator.StartJob` context input has `type="string"`, and `releaseKey` is a literal process key.
2. The agent is called with `Orchestrator.StartJob` and its release key, not `Orchestrator.StartAgentJob`.
3. Variable ids have no underscores (`VarRecordId`).
4. Script results are set with `<uipath:type value="BPMN.Variables">` and a `custom="true"` output
   (`source="=js:true"`, `source="=js:(vars.VarPollCount || 0) + 1"`).
5. Every task has a `<uipath:inputSchema type="jsonSchema">`, and each output argument is mapped on its own.

## The timer loop: PT2M with a PollCount cap

The dry-run file used `PT30S` with no cap, which started a serverless status job about every 40 seconds per
waiting instance. This reference changes that loop:

- `Timer_Wait` is `PT2M`;
- `Script_CountPoll` (BPMN.Variables) adds 1 to `PollCount` after each timer, before `Task_Status`;
- `Approved?` loops back while the state is NEEDS_AP_REVIEW or READY_FOR_APPROVAL **and** `PollCount < 6`;
- `Flow_PollCap` sends the same states to the Held end once `PollCount >= 6` (about 13 minutes).

`uip maestro bpmn validate` passes on this file (uip 1.200.1, `Status: Valid`). The cap was added after the dry
run, so the PT2M timer and PollCount path have not yet run in a live instance; check one `uip maestro bpmn debug`
of the reviewer path before the cohort relies on it.

## Packaging, deploy and run

- Refresh, then grep `resources/` for `access_token`, `ERP_PO_LOOKUP_URL` and `environmentVariables`. Clear any
  hit with `uip solution resources edit <key> --patch '{"environmentVariables":""}'` before pack, and grep the zip.
- `uip solution deploy config link <config> <name> --name <name> --folder-path "Agentic Bootcamp/APAutomation_<user_name>"`
  for each of the 5 Lab processes, so deploy reuses them instead of installing copies in the new child folder.
- There is no `deploy upgrade` in uip 1.200.1. A new version is a new deployment name (a sibling folder).
- Run:
  `uip maestro bpmn process run "<ProcessKey>:<version>" <solution-folder-key> --release-key <key> --feed-id <feed> --inputs '{"FileName":"<file in InvoiceInbox_<user_name>>"}'`
- Monitor: `uip maestro bpmn instance element-executions <instance-id> --folder-key <solution-folder-key>`.

## Known gap

The `Approved?` gateway trusts the reviewer's APPROVED write. With the Lab 6 rule, an invoice still in
NEEDS_AP_REVIEW (incomplete approval evidence) can be approved and is then posted. That is the intended
reviewer decision in this bootcamp; the detail panel shows the missing fields before the click.
